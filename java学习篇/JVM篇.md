# JVM 篇

## 一、编译器和解释器

| 对比 | 编译器 | 解释器 |
|------|:------:|:------:|
| **输出结果** | 独立的目标代码文件（`.exe` / `.class`） | 不生成持久化文件，直接运行 |
| **典型例子** | C++ → 机器码、Java（javac）→ 字节码 | Python |
| **跨平台** | 不可跨平台 | 可跨平台 |

> [!info] Java 是**编译器（javac）和解释器（JVM）的结合**：
> 源码 → `javac` 编译 → `.class` 字节码 → JVM 解释执行 → **实现跨平台**

## 三、类加载器（Class Loader）

### 类加载过程（7 个阶段）

```
加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
├──────── 连接（Linking） ────────┤
```

| 阶段 | 说明 |
|:----:|------|
| **① 加载（Loading）** | 将字节码（`.class` / jar）转为二进制字节流加载到内存，生成 `Class` 对象 |
| **② 验证（Verification）** | 校验字节码格式，保证 JVM 安全 |
| **③ 准备（Preparation）** | 为**类变量（static）** 分配内存并赋**默认零值**（0 / null / false） |
| **④ 解析（Resolution）** | 将常量池中的**符号引用**转化为**直接引用**（内存地址） |
| **⑤ 初始化（Initialization）** | 执行类构造器 `<clinit>()`，为类变量赋**代码指定的值** |
| **⑥ 使用** | 主动使用该类 |
| **⑦ 卸载** | 从方法区移除 |

### 三大类加载器

| 类加载器 | 加载目标 | 特点 |
|:--------:|----------|------|
| **Bootstrap ClassLoader** | `JAVA_HOME/lib` 核心类（rt.jar） | C++ 实现，Java 中不可见（`getClassLoader() → null`） |
| **Extension ClassLoader** | `JAVA_HOME/lib/ext` 扩展类 | Java 实现，加载 `javax.*` |
| **Application ClassLoader** | **classpath** 中的用户代码 | 默认加载器，最常用 |

### 双亲委派模型（Parent Delegation）

```
① 自底向上问：
   Application → Extension → Bootstrap（询问是否已加载）
② 自顶向下试：
   Bootstrap → Extension → Application（尝试加载）
```

> [!tip] **双亲委派的好处**
> - 避免核心类被自定义类替换（如 `java.lang.String`）
> - 保证 Java 核心库的类型安全

## 四、运行时数据区（内存结构）

```
┌────────────────────────────────────────────┐
│              线程私有区                     │
│  ┌────────────┐  ┌─────────┐  ┌─────────┐ │
│  │程序计数器   │  │虚拟机栈  │  │本地方法栈│ │
│  │ PC Register│  │VM Stack │  │Nat.Stack│ │
│  └────────────┘  └─────────┘  └─────────┘ │
├────────────────────────────────────────────┤
│              线程共享区                     │
│  ┌──────────────────────┬──────────────┐   │
│  │        堆（Heap）     │  方法区/元空间 │   │
│  │  新生代 │ 老年代       │  (Metaspace)  │   │
│  └──────────────────────┴──────────────┘   │
└────────────────────────────────────────────┘
```

### 1. 程序计数器（PC Register）

- **作用**：记录当前线程执行的字节码指令地址
- Java 方法：记录虚拟机字节码指令地址
- Native 方法：值为 `undefined`

### 2. Java 虚拟机栈（VM Stack）

- **作用**：存储**栈帧（Stack Frame）**，每个方法调用对应一个栈帧入栈，方法结束出栈
- 栈帧包含：**局部变量表、操作数栈、动态链接、方法返回地址**

#### 栈帧结构

| 组成部分 | 说明 |
|----------|------|
| **局部变量表** | 存储方法参数和局部变量（`this`、基本类型、对象引用） |
| **操作数栈** | 后进先出（LIFO），存储中间结果、参数、返回值 |
| **动态链接** | 将符号引用转换为直接引用，支持多态 |
| **方法返回地址** | 正常返回 → PC 下一条指令；异常返回 → 异常处理器表 |

> [!info] **指令执行示例**
> ```
> iload_0  → 将局部变量 0（值 33）压入操作数栈
> iload_1  → 将局部变量 1（值 44）压入操作数栈
> iadd     → 弹出 33 和 44，相加得 77，压入栈
> istore_2 → 弹出 77，存入局部变量表下标 2
> ```

#### 寄存器虚拟机 vs 栈虚拟机

| 对比 | 寄存器虚拟机 | 栈虚拟机 |
|:----:|:------------:|:--------:|
| **位置** | CPU 中 | 内存中 |
| **速度** | 快 | 较慢 |
| **操作数** | 显式 | 隐式（栈操作） |
| **指令长度** | 长 | 短 |
| **代表** | Android Dalvik | **JVM** |

### 3. 本地方法栈（Native Method Stack）

- 与虚拟机栈类似，但为 **Native** 方法服务

### 4. 堆（Heap）

- **所有线程共享**，JVM 启动时创建
- 存储对象和数组
- **GC 主要区域**，分为新生代和老年代

### 5. 方法区 / 元空间（Metaspace）

- **JDK 8+**：用**元空间**（本地内存）取代永久代
- 存储：类结构信息（类的定义、方法、字段、字节码指令）
- 包含**运行时常量池**：用于查找方法/变量的实际内存地址

## 五、JVM 中 new 一个对象的过程

```
检查（类加载） → 分配内存 → 初始化零值 → 设置对象头 → 执行构造方法
```

1. **检查**：检查类是否已加载，未加载则触发类加载
2. **分配内存**：在堆中为对象分配空间
3. **初始化零值**：将所有字段初始化为默认值（0 / null / false）
4. **设置对象头**：设置 Mark Word、类指针、GC 分代年龄等
5. **执行构造方法**：执行 `<init>()`，按代码赋初始值

## 六、垃圾回收机制（GC）

> [!info] GC 负责自动回收堆中不再被引用的对象，JVM 开发者无需手动释放内存。

### 判断对象是否存活

#### 1. 引用计数法（主流 JVM 不采用）

每个对象维护一个引用计数器，为 0 则回收，缺点：**无法解决循环引用**。

#### 2. 可达性分析算法（✅ JVM 采用）

以 **GC Roots** 为起点，向下搜索引用链，不可达的对象即为可回收对象。

**GC Roots 包括**：
- 虚拟机栈（栈帧中局部变量表）引用的对象
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中 JNI 引用的对象

### 四大引用类型

| 类型 | 回收时机 | 用途 |
|:----:|----------|------|
| **强引用** | 永不回收 | `new` 对象，即使 OOM 也不回收 |
| **软引用** | 内存不足时回收 | **缓存**（`SoftReference`） |
| **弱引用** | 下次 GC 时回收 | **缓存/框架**（`WeakReference`，如 ThreadLocal） |
| **虚引用** | 随时可能回收 | **跟踪对象回收**（`PhantomReference`） |

### 垃圾回收算法

| 算法 | 原理 | 优缺点 |
|:----:|------|:------:|
| **标记-清除** | 标记垃圾 → 直接清除 | 有**内存碎片** |
| **标记-复制** | 将存活对象复制到另一块区域 | **无碎片**，但浪费空间 |
| **标记-整理** | 标记垃圾 → 存活对象向一端移动 | **无碎片**，但效率低 |
| **分代收集** | 新生代用复制，老年代用标记整理 | **主流方案** |

### 分代收集

```
新生代（Young Gen）             老年代（Old Gen）
┌────────┬─────┬──────────┐    ┌────────────┐
│  Eden  │ S0  │   S1     │ →  │   Old      │
│  80%   │ 10% │   10%    │    │            │
└────────┴─────┴──────────┘    └────────────┘
     │ Minor GC (频繁)         Major GC / Full GC (较少)
     │ 标记-复制                 标记-整理 / 标记-清除
     ▼
对象晋升：每次 Minor GC 存活 → 年龄 +1 → 到阈值（默认15）→ 进入老年代
```

### 垃圾收集器

| 收集器 | 区域 | 算法 | 特点 |
|:------:|:----:|:----:|------|
| **Serial** | 新生代 | 复制 | 单线程，暂停所有用户线程 |
| **ParNew** | 新生代 | 复制 | Serial 的多线程版本 |
| **Parallel Scavenge** | 新生代 | 复制 | 关注**吞吐量** |
| **Serial Old** | 老年代 | 标记-整理 | Serial 老年代版 |
| **Parallel Old** | 老年代 | 标记-整理 | Parallel 老年代版 |
| **CMS** | 老年代 | 标记-清除 | 追求**低停顿**，会产生碎片 |
| **G1（Garbage First）** | 整堆 | 分代+Region | **JDK 9+ 默认**，可预测停顿时间 |

## 七、JIT（即时编译器）

JIT 是 JVM **性能优化的核心组件**，在运行时将热点字节码编译为机器码。

### 主要优化技术

#### 1. 方法内联（Method Inlining）

```java
// 优化前
int result = add(a, b);
// 优化后（内联）
int result = a + b;
```

#### 2. 逃逸分析（Escape Analysis）

分析对象作用域，进行优化：
- **栈上分配**：对象不逃逸时直接在栈上分配（减少 GC 压力）
- **标量替换**：将对象拆解为基本类型
- **同步消除**：去掉不必要的锁

#### 3. 公共子表达式消除

```java
// 优化前
int a = b * c + d;
int e = b * c + f;
// 优化后
int temp = b * c;
int a = temp + d;
int e = temp + f;
```

#### 4. 循环优化

- **循环展开（Loop Unrolling）**：减少循环次数
- **循环剥离（Loop Peeling）**：处理边界条件
- **循环判断外提（Loop Invariant Code Motion）**：将不变代码提到循环外

## 八、.class 文件结构

class 文件是一串连续的二进制，主要包含：

| 组成部分 | 说明 |
|:--------:|------|
| **魔数** | `0xCAFEBABE`，标识 class 文件 |
| **版本号** | 编译版本兼容性 |
| **常量池** | 类、接口、方法、字段的符号引用和字面量 |
| **访问标记** | `public` / `final` / `abstract` 等 |
| **类索引 / 父类索引 / 接口索引** | 确定继承关系 |
| **字段表** | 字段名、类型、签名 |
| **方法表** | 方法名、参数、签名、字节码指令 |
| **属性表** | 字段初始值、方法字节码指令等 |
