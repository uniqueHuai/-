# 大模型本地部署

## 一、为什么需要本地部署

### 本地部署 vs 云端 API

```
对比维度          云端 API (Claude/GPT)          本地部署 (Ollama/vLLM)
────────────────────────────────────────────────────────────────────
数据安全          数据离开企业网络               数据完全本地
延迟              网络延迟 200-1000ms            本地推理 10-100ms
成本              按 Token 计费                  一次性 GPU 投入 + 电费
隐私合规          需签 DPA 协议                  完全自主可控
模型选择          提供商限定                      社区任意模型
可用性            依赖网络和 API 状态            完全离线可用
可定制性          只支持超参数调整               可量化/微调/剪枝
扩展性            自动扩缩容                     需自建推理集群
维护成本          几乎为零                       需运维团队
适用场景          原型验证、弹性需求              数据敏感、高频调用、离线场景
```

## 二、Ollama ⭐

### 简介

**Ollama** 是 2026 年最流行的本地模型运行工具，以其**极简操作**著称。只需一行命令即可运行主流模型。

### 安装

```bash
# Linux / macOS
curl -fsSL https://ollama.com/install.sh | sh

# Windows（2026 已原生支持）
winget install Ollama.Ollama

# Docker
docker run -d --gpus all -v ollama:/root/.ollama -p 11434:11434 ollama/ollama
```

### 运行模型

```bash
# 基础用法
ollama run qwen4:7b          # 通义千问 4（7B）
ollama run llama4:8b         # Llama 4（8B）
ollama run deepseek-r2:7b    # DeepSeek-R2（7B）
ollama run phi-4:14b         # Phi-4（14B）
ollama run gemma3:27b        # Gemma 3（27B）

# 推理模型
ollama run deepseek-r2:70b   # DeepSeek-R2 推理版（70B）

# 多模态模型
ollama run qwen4-vl:7b       # 通义千问 4 视觉版

# 交互模式
>>> 什么是 AI Agent？

# 一次性问答
ollama run qwen4:7b "用 Java 实现一个单例模式"

# API 模式（默认启动）
curl http://localhost:11434/api/generate -d '{
  "model": "qwen4:7b",
  "prompt": "用 Java 实现二分查找"
}'
```

### 模型管理

```bash
# 查看已下载的模型
ollama list

# 拉取模型
ollama pull qwen4:7b

# 删除模型
ollama rm qwen4:7b

# 查看模型详情
ollama show qwen4:7b

# 创建自定义模型（基于 Modelfile）
ollama create my-model -f Modelfile
```

```bash

```

### 性能调优

```bash
# GPU 层数（默认全部加载到 GPU）
ollama run qwen4:7b --num-gpu 2

# 并行请求数

# 保持模型在内存中（减少加载时间）
```

## 三、vLLM ⭐

### 简介

**vLLM** 是生产级 LLM 推理引擎，使用 **PagedAttention** 技术大幅提升推理吞吐量。适合企业级本地部署。

### 安装与启动

```bash
# 安装
pip install vllm

# 启动 OpenAI 兼容 API
python -m vllm.entrypoints.openai.api_server \
    --model deepseek-r2:7b \
    --gpu-memory-utilization 0.9 \
    --max-model-len 32768 \
    --dtype auto \
    --port 8000

# 使用 tensor parallel 多 GPU
python -m vllm.entrypoints.openai.api_server \
    --model deepseek-r2:70b \
    --tensor-parallel-size 4 \
    --port 8000
```

### vLLM 的核心优势

```text
vLLM 与传统推理的对比

传统推理（HuggingFace Transformers）
├── 显存浪费：每个请求单独分配 KV Cache
├── 低吞吐：无法有效批处理
├── 高延迟：动态批处理不高效
└── 大模型 OOM：70B 模型需要超大显存

vLLM（PagedAttention）
├── 显存高效：类操作系统的分页管理 KV Cache
├── 高吞吐：连续批处理（Continuous Batching）
├── 低延迟：几乎 100% GPU 利用率
└── 支持大模型：70B/405B 模型也能运行
└── 吞吐量提升：2-4x 于 HF Transformers
```

### API 调用

```bash
# 兼容 OpenAI API，可以无缝切换
curl http://localhost:8000/v1/chat/completions -d '{
  "model": "deepseek-r2:7b",
  "messages": [
    {"role": "system", "content": "你是 Java 开发助手"},
    {"role": "user", "content": "什么是虚函数？"}

```

## 四、llama.cpp

### 简介

**llama.cpp** 是纯 C/C++ 实现的推理引擎，支持 **CPU 推理** 和多种 GPU 后端，是资源受限场景的首选。

### 核心特性

```text
llama.cpp 适用场景
├── CPU 推理：无 GPU 也能运行
├── 量化支持：最广泛的量化方案
├── 边缘设备：树莓派、手机都能跑
├── 嵌入式：IoT 设备集成
├── 跨平台：Windows/Linux/macOS/Android/iOS
└── 最小依赖：纯 C++，无 Python 依赖

量化方案
├── Q2_K：极低精度，极致压缩（需测试效果）
├── Q3_K：低精度
├── Q4_K_M：⭐ 推荐：质量/大小平衡
├── Q5_K_M：较高精度
├── Q6_K：高精度
├── Q8_0：接近无损
└── F16：原始精度
```

### 使用

```bash
# 下载量化模型
wget https://huggingface.co/bartowski/Qwen4-7B-GGUF/resolve/main/qwen4-7b-q4_k_m.gguf

# 启动服务器（兼容 OpenAI API）
./llama-server \
    -m qwen4-7b-q4_k_m.gguf \
    --host 0.0.0.0 \
    --port 8080 \
    --n-gpu-layers 35 \
    --ctx-size 32768

# 交互模式
./llama-cli \
    -m qwen4-7b-q4_k_m.gguf \
    -p "Java 和 C++ 的区别是什么？" \
    -n 512
```

### 混合部署（本地 + 云端）

```java
// ⭐ 智能路由：简单用本地，复杂用云端
@Service
public class HybridModelRouter {

    private final ChatClient localModel;    // Ollama/vLLM
    private final ChatClient cloudModel;    // Claude / GPT

    public HybridModelRouter(
            @Qualifier("localChatClient") ChatClient local,
            @Qualifier("cloudChatClient") ChatClient cloud) {
        this.localModel = local;
        this.cloudModel = cloud;
    }

    public String chat(String message) {
        // 快速判断任务复杂度
        TaskComplexity complexity = estimateComplexity(message);

        return switch (complexity) {
            case SIMPLE -> localModel.prompt()
                .user(message).call().content();

            case COMPLEX -> cloudModel.prompt()
                .user(message).call().content();

            case HYBRID -> {
                // 先用本地模型做初步处理
                String localResult = localModel.prompt()
                    .user("提取关键信息：" + message)
                    .call().content();

                // 云端做最终处理
                yield cloudModel.prompt()
                    .user("基于以下信息回答：\n" + localResult + "\n问题：" + message)
                    .call().content();
            }
        };
    }

    /**
     * 快速判断任务复杂度
     * - 短查询、简单问答 → SIMPLE
     * - 多步推理、代码生成 → COMPLEX
     */
    private TaskComplexity estimateComplexity(String message) {
        if (message.length() < 50 && !message.contains("代码")
            && !message.contains("分析") && !message.contains("设计")) {
            return TaskComplexity.SIMPLE;
        }
        if (message.contains("设计") || message.contains("架构")
            || message.contains("优化") || message.contains("安全")) {
            return TaskComplexity.COMPLEX;
        }
        return TaskComplexity.HYBRID;
    }

    enum TaskComplexity { SIMPLE, COMPLEX, HYBRID }
}
```

### 关键性能指标

```text
性能监控指标
═══════════════════════════════════════

吞吐量（Throughput）
├── 定义：每秒生成的 Token 数（tokens/s）
├── 7B Q4： 约 50-80 tokens/s (RTX 4090)
├── 70B Q4：约 10-20 tokens/s (A100)
└── 目标：>30 tokens/s 体验良好

首 Token 延迟（TTFT）
├── 定义：从请求到第一个 Token 的时间
├── 目标：<500ms
└── 优化：保持模型 warm、增加 GPU 层数

KV Cache 命中率（仅缓存场景）
├── 定义：缓存命中的请求比例
├── 目标：>60%（语义缓存）
└── 意义：减少重复计算，降低延迟

显存利用率
├── 定义：GPU 显存使用率
├── 正常：80-95%
├── 过高：>95% → OOM 风险
└── 过低：<50% → 浪费资源，可加大模型
```

## 八、本地部署最佳实践

### 部署决策树

```
需要本地部署吗？
│
├─ 数据必须本地？───────── 是 ──▶ 本地部署
│
├─ 延迟要求 < 100ms？───── 是 ──▶ 本地部署
│
├─ 调用量 > 100万 Token/天？── 是 ──▶ 算成本账
│   ├─ API 费用 > GPU 折旧？── 是 ──▶ 本地部署
│   └─ API 费用 < GPU 折旧？── 是 ──▶ 继续用 API
│
├─ 需要离线可用？───────── 是 ──▶ 本地部署
│
└─ 以上都是否 ────────────────▶ 云端 API 即可
```

### 部署 checklist

```text
□ 1. 硬件评估
   □ 确定模型参数量
   □ 计算所需显存（权重 + Cache + 开销）
   □ 选择 GPU 型号和数量
   □ 评估是否支持多卡（tensor parallel）

□ 2. 模型选择
   □ 选择基础模型（Qwen / DeepSeek / Llama）
   □ 选择量化方案（推荐 Q4_K_M）
   □ 选择推理引擎（Ollama / vLLM）
   □ 测试模型效果

□ 3. 性能调优
   □ 设置合适的上下文长度
   □ 调整 batch size 和 GPU 层数
   □ 启用连续批处理（vLLM）
   □ 配置缓存策略

□ 4. 运维保障
   □ 设置 GPU 监控告警
   □ 配置自动重启
   □ 建立模型版本管理
   □ 制定扩容方案

□ 5. 安全合规
   □ 限制 API 访问来源
   □ 配置认证鉴权
   □ 审计日志记录
   □ 数据加密存储
```

> [!tip] **给 Java 开发者的建议**
> 本地部署最大的好处是**开发调试体验**的提升——开发时用 Ollama 跑 7B 模型，测试通过后切换到云端生产模型，代码零改动。Spring AI 的抽象层让这种切换只需改一行配置。建议：开发环境用 `qwen4:7b`（中文强），生产环境根据需求选择 Claude/GPT 或 vLLM 自建。
